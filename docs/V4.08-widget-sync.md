# V4.08 小组件同步说明

本次仅修改搞节奏。现有三个组件为「月度总览」（large）、「今日指标」（small）和「长期目标」（small），不新增尺寸或更改 kind。

## 已确认的问题与证据边界

旧实现存在可独立确认的可靠性缺陷：镜像写入错误被吞掉，保存端仍清除刷新标记；组件读取失败后尝试备用路径并返回空白资料；组件未校验主库 schema；Timeline 只提供当前和下一次午夜两个 entry。上述问题可能造成更新遗漏、伪造零值或长期延迟时日期停止推进。

升级前只读检查显示，已安装主程序与扩展版本一致，签名和 App Group entitlement 有效，未发现同标识旧宿主或旧扩展登记。当时真实主库与 App Group 镜像逐字节一致，系统组件 Timeline 缓存与请求日志也已在当日推进。现有日志没有保存每次读取的业务摘要，缓存更新时间不能证明桌面显示了对应内容。因此，用户反馈的固定旧日期尚不能归因于某一个已经证实的实际桌面故障点。

文件 mtime 是写入时间，不能替代真实业务内容变更时间；新 entry.date 也不能被报告成资料更新时间。

旧存档未记录独立的业务修改时间。首次新格式发布以原主库 mtime 建立时间基线，不反推此前具体业务操作的时刻；之后业务摘要不变时保留该基线。旧格式兼容读取仅标注“镜像保存”，业务修改与生成时间保持未知。

## 本次实现

- 主程序在原有完整 JSON 镜像之外发布原子快照封装，包含 schema、业务摘要、完整文件摘要、源资料时间、业务内容时间、生成时间及版本。保留一份经过验证的上一版内容。
- 镜像失败保留待办，主程序存活时以有界维护重试；专注/睡眠结束或取消进入空闲后仍会重试。退出遇到主库保存失败时返回失败并阻止静默丢失会话。
- 组件只读 App Group 内验证通过的当前封装、上一版封装或首次升级前的兼容镜像。失败显示不可用状态，不将备用沙箱目录或默认零值作为真实资料。
- Timeline 提供当前及未来 32 个本地午夜 entry，跨日、月和 DST 使用日历运算；正在运行的专注使用系统动态计时，并在当前日期边界截断。
- 业务摘要区分打卡、目标、行动、琐事、会话锚点及完成记录与纯游戏结算；只有真实业务内容变化才推进业务时间。

## 验证时间链

应分别记录业务内容变化时间、镜像生成时间、组件读取时间、entry 对应日期及最终桌面显示时间，并以业务摘要/版本匹配各阶段。没有业务变化时，业务时间保持不变。发布失败保留最后有效镜像及重试状态；缺失、损坏、不可读取或过新 schema 不应被发布为默认空白库。

必要的隔离定向测试覆盖保存与镜像失败重试、组件严格读取和最后有效内容、各业务投影、动态专注计时区间、跨午夜/跨月/DST 的未来 Timeline。此类测试不等于实际桌面验收，也不代表 WidgetKit 有固定刷新秒数。

遵循最新测试偏好，未自动运行冒烟测试，未为验收启动主程序、浏览器或测试窗口。首次添加/重加、多个实例、实际记录增删改后的桌面变化、关闭窗口/退出、系统重启、睡眠唤醒、时区变化以及实际显示延迟，仍需用户在桌面操作后观察。不得以 reload 请求成功、隔离测试通过或重新添加组件作为这些项目通过的依据。

### 2026-11-02 后续实机核对（V4.09）

以上为 V4.08 发布时的验证边界，后续在明确授权下补做了实机操作。打卡、目标、关联行动及琐事的最少创建、编辑、删除已核对主库、镜像及系统读取；两次短计时取消、约70秒专注完成和约30秒睡眠完成均实际执行。完成记录使用开始时捕获的同一会话 ID，零金币奖励和共享睡眠记录分别绑定本次唯一增量；随后按精确 ID 清理，保留真实自然成长及正常睡眠删除墓碑，原资料与设置保持原值。

三个正式安装的组件均有实际 `getTimeline` 后读取当前快照的日志，包含版本、业务时间、生成时间和摘要。专注完成的当次读取落在同秒或次秒，不构成固定刷新时限。已通过桌面组件的实际辅助功能内容读取，核对目标数及睡眠完成后的指标；部分系统截图只能取得灰色背景，这些图片没有作为可见内容通过的证据。

关闭主业务窗口后，两次相隔约8秒的公开窗口采样均确认窗口不在屏幕上且主进程仍是同一 PID；重开后保留同一会话及真实起点，完成结算包含关窗期间的时间。此结果不代表逐秒写盘或长时间运行时限保证。跨日、唤醒及时区等已完成的实机分段另有私有记录，不重复造样本。

已用完整序号及精确 kind 核对两枚真实桌面目标实例，目标数、各项进度及业务更新时间一致；正常移除其中一枚后，同 kind 重加已生成新的桌面实例。重加实例的身份及数量检查由正常移除前的脚本守卫路径和执行后的桌面窗口变化共同佐证；该脚本在后续剩余实例的身份复核处中止，未返回重加实例的完整文本，因此不宣称已再次逐项保存其全部进度。最后一次只执行剩余自有实例的正常菜单移除，并保存其实际内容。系统完成移除后，公开窗口复核确认全部临时组件均已消失，原有其他组件的标识和位置完整保留，主库摘要不变。诊断原件、业务标题、完整摘要、记录 ID、备份与截图不随源码或发行包发布。

## SharedSleep 交接

本次保留既有 SharedSleep 协议、历史迁移与去重规则，不修改搞健康源码或单方面更改共同 schema。

搞节奏完全退出时，搞健康的新睡眠记录不会自行写入搞节奏 App Group 镜像；当前需要搞节奏唤醒或下次启动后同步。若需要两应用都退出或搞节奏退出时立即同步，后续双方应约定带版本的共享只读睡眠投影、原子发布与通知/刷新责任，并分别测试兼容性、去重、删除墓碑和失败重试。本次不通过重复全量历史导入规避该限制。

## 发布与资料保护

沿用原资料路径和钥匙串服务。升级前退出相关主程序，备份并核验主库、App Group、设置、全部附件及 SharedSleep 数据库与 WAL；安装后逐项比较。仅精确处理本应用失效登记。个人记录、完整业务摘要、诊断原件与备份保存在私有位置，不进入源码仓库或发行包。

安装流程可调用 `RhythmApplicationLifecycle.publishSavedWidgetSnapshot`，从已验证的原路径只读主库存档，发布首个新格式快照。该入口不初始化运行时或业务 Store、不创建窗口、不重写主库；此数据迁移不构成主程序或实际桌面验收。回退程序应保留到实际桌面验收完成。
