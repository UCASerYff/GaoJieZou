# 搞节奏「晨光工作台」界面重构设计

日期：2026-11-10  
目标版本：V4.11 / build 12

## 1. 目标与边界

本次只重构搞节奏 macOS 应用的导航、视觉系统和记录界面，保留全部现有业务能力。用户已明确选择五个一级工作台的「晨光工作台」方向，不再要求与其他搞系列应用保持一致。

保留专注、睡眠、习惯、事项、长期与短期目标、统计、健康、旅行足迹、全部奖励游戏和小组件。现有数据库、资料路径、记录 ID、附件、共享睡眠协议、奖励去重、游戏进度、设置和钥匙串服务不变，不进行业务数据迁移。

移除搞节奏的自动备份能力及相关设置入口。本次升级和清理不创建或保留自动备份、手动资料备份、迁移/恢复副本、升级快照或旧程序回滚副本；既有备份在准确识别后删除。CSV 与诊断信息导出仍属于用户主动导出的业务数据，不属于应用备份。现用业务资料、数据库、设置、附件和钥匙串不得删除或上传。

## 2. 信息架构

主窗口取消长侧栏，改为顶部五个胶囊式一级入口：

| 一级工作台 | 二级内容 |
| --- | --- |
| 今天 | 今日状态、当前专注、习惯与睡眠摘要、最近记录、快捷操作 |
| 节奏 | 专注、睡眠、习惯、事项、目标、统计；通过页内标签切换 |
| 健康 | 今日、全部记录、统计趋势、快速事项；喝水、睡眠、饮食、运动、体重作为记录类型和筛选条件 |
| 足迹 | 地图、旅行、时间轴；常驻城市并入地图与城市详情 |
| 乐园 | 农场、牧场、渔场、庄园图鉴、荒岛生活、旅行列车；以场景卡片进入 |

保留原 `RhythmSection` 作为业务页面与深链的稳定标识，在其上增加工作台和页内导航映射，不重命名持久化记录或外部路由。通知、菜单命令、旧场景存储值及 `gaojiezou`、`gaojiankang`、`gaozuji` 链接均通过同一映射进入正确的工作台和二级页面。

顶部提供全局“＋记录”菜单，按当前工作台优先展示对应记录类型。窄窗口下导航允许紧凑显示，但不能产生不可达的入口。

## 3. 视觉系统

- 浅色画布采用奶油白，主色为鼠尾草绿，主要操作使用陶土橙，辅以低饱和沙色和柔和植物绿。
- 深色模式采用暖炭灰与低饱和绿，保持文字、边框和焦点状态的对比度，不做简单颜色反转。
- 页面标题使用具有手账感的系统宋体组合，正文、数字和控件继续使用高可读性的系统字体；计时数字保留等宽数字。
- 卡片采用连续圆角、细边框、轻阴影与充足留白，不使用厚重渐变或装饰性玻璃堆叠。
- 图标、记录类型色、按钮、空状态、进度条和标签来自统一主题组件；健康与足迹原有业务插画和游戏资源保留。

## 4. 页面与组件

### 4.1 主壳

新增轻量工作台导航层，负责一级页面、二级页面、全局记录入口和窗口标题。主壳只管理展示状态，不拥有业务数据。`RhythmStore`、健康 Store、足迹 Store 及既有生命周期控制继续作为业务权威。

### 4.2 今天

首页由问候与日期、当前专注或快捷开始卡、习惯与睡眠摘要、今日记录组成。卡片可直接进入对应二级页面；不复制业务结算逻辑，不制造另一份记录。

### 4.3 节奏、健康与足迹

二级导航使用标签或分段控件。健康记录类型不再占据一级入口，统一在时间流中展示并可筛选。足迹保留地图、旅行记录、照片和城市详情；仅调整呈现层级，不改变地点与旅行关联。

### 4.4 乐园

六个既有游戏入口聚合为卡片式索引，显示真实的进行状态或库存摘要。进入游戏后提供清晰返回乐园的方式，游戏场景和货币体系保持独立。

### 4.5 记录与编辑

统一记录容器的标题图标、说明、分组表单、可选字段、错误提示和固定底部操作区。覆盖专注/睡眠、习惯、事项、目标、健康记录和旅行手记等高频界面。保留现有应用内浮层及 ESC、回车、取消、未保存确认等行为，不重新引入已解决的原生 Sheet 首开延迟。

## 5. 数据流与兼容

导航状态只决定展示哪个现有页面；保存仍调用原有 Store 和 Engine。记录保存后的统计、奖励、共享睡眠和组件刷新沿用既有链路。旧深链先解析为 `RhythmSection`，再映射为工作台和二级页面，保证一个链接只处理一次。

界面重构不修改数据格式，不运行迁移或激活，不把缺失资料当成空白。加载失败继续禁用相关操作并显示现有错误；表单校验失败保留草稿并在表单内提示，保存失败不得表现为成功。

## 6. 备份移除与升级清理

识别并移除搞节奏自动备份的调度、执行入口和设置界面，不影响用户主动 CSV/诊断导出。安装与发布流程不得调用 snapshot、预更新备份或恢复副本命令。

删除对象必须逐项核对真实路径、类型和内容，仅限搞节奏旧程序、旧安装包、中间构建产物、临时副本及既有备份。用户数据目录、App Group 现用数据库与组件镜像、UserDefaults、附件和钥匙串全部保留。项目目录最终只保留会推送到仓库的源码、资源、文档、测试，以及最新版安装包与校验文件。

新 `.app` 生成前必须位于 `.noindex` 容器。安装后核对真实副本、Spotlight 与 LaunchServices，确保只有 `/Applications/搞节奏.app` 一个有效入口；不以空查询或沙箱结果冒充唯一性通过。

## 7. 验证与发布

1. 为导航映射、二级页面和记录组件增加或更新回归测试；运行受影响的现有业务测试。
2. 使用 `scripts/build.sh` 构建主程序和小组件，版本升为 4.11、构建号升为 12，沿用既定 Apple Development 签名。
3. 在真实安装环境验证五个工作台、页内导航、主要记录新增/修改、旧深链、专注与睡眠状态、游戏入口和小组件；测试窗口随用随关。
4. 安装前后以文件清单和摘要核验真实资料与附件，不创建备份。失败则停止并如实报告，不删除现用资料。
5. 验证成功后删除旧程序、旧安装包、构建产物、临时副本和既有备份，保留最新版 ZIP 与 SHA-256。
6. 更新 README 和发布说明，提交并推送 `main` 到 `UCASerYff/GaoJieZou`，创建 V4.11 Release，仅上传最新版安装包、校验文件和源码；不上传用户数据、备份或凭据。

## 8. 完成标准

五个一级入口及全部既有功能均可到达；记录界面采用统一新视觉；旧深链、数据、奖励、附件、游戏和小组件不回归；自动备份功能及既有备份被移除；本机只有新版本一个有效安装入口；GitHub 源码和 V4.11 Release 与本机交付一致。
